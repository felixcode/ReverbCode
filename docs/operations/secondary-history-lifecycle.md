# Secondary history lifecycle

`gc:activity` is metadata-only and uses the existing bounded, nonqueued Store maintenance transaction. It removes only48h-old anonymous terminal command/file-change/reasoning/usage/error rows attached to a uniquely identified native terminal turn with an existing retained turn-expiry marker. Pending input, handoff, recent updated_at, no-turn, missing proof, native item/request identities and system/plan/approval/user_input anchors survive. Activity and activity_output audits retire atomically with their source. The turn marker stays. UpsertActivity checks this same expired old-turn proof for this anonymous class, so a late replay cannot reinsert a new anonymous activity ID; current other turns remain writable.

`gc:audit` uses a bounded SQLite rowid prefix only for the audit table. It removes known non-provider-event kinds whose source is absent and whose marker expiry itself is older than48h. Source-present recovery markers, unknown kinds/invalid timestamps and provider_event markers stay. Snapshot expiry and payload replay consumers join their source rows, so orphan audit markers no longer serve them. No age-only deletion of valid source-bound markers.

model_usage_events remains a financial/idempotency ledger: usage.sql AggregateUsageBySessionHarnessModel and ListCompactSessionUsage SUM it directly; GetModelUsageEventByKey uses(binding_id,source_event_key) for replay; cost/legacy repair reads provider_usage_json. There is no independent durable aggregate proving row deletion safe. This change deliberately retains numeric costs/tokens, event keys and provider usage objects, with reason accounting_dedup_repair. A future ledger compaction requires atomic persisted aggregate plus replay tombstones and invariant tests, not merely DELETE old events.

Production rows are not mutated by source preparation. Logical bytes deleted do not equal OS space reclaimed. Existing invalid UTF8 bodies and unproved/no-turn old activities remain protected; no encoding replacement or fabricated all-history-within48h claim.
