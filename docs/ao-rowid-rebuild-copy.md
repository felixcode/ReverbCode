# Offline ROWID-preserving snapshot rebuild

`backend/cmd/ao-rowid-rebuild-copy` is a separate copy-only maintenance program.
It does not register an AO command or HTTP endpoint and never publishes, swaps,
starts, stops, or edits a live AO database. Formal production downtime and the
final installation remain separate operations.

The AO history rollback cut and stable ordering use implicit ROWIDs in
`conversation_turns`; latest interface transition selection also uses ROWID.
Plain `VACUUM`/`VACUUM INTO` may change those IDs. This tool instead creates a new
`auto_vacuum=INCREMENTAL` database and explicitly copies the source ROWID along
with every writable column, inside SQLite with `INSERT ... SELECT`. Payloads do
not cross Go JSON, floating-point conversions, or reports.

## Input and output boundary

Run only on a closed, verified, private static snapshot on a server-local
filesystem, after any copy-only cleanup writer has closed all connections and
the snapshot has no WAL/SHM/journal sidecars. Never run against a mounted NFS
path or the original `ao.db`. The live AO database stays on its host.

The expected source SHA-256 is mandatory. Paths must be absolute, clean and
symlink-free. The source must be a regular 0600 file owned by the invoking user,
with one hard link. Unknown process reference visibility is refused. A hash and
SQLite lock alone are not proof that an arbitrary source is offline.

For real execution, use an independently reviewed isolated-volume runner: one
closed source volume is bound read-only, one brand-new private candidate volume
is writable, there are no other writable consumers, and the process runs as
UID/GID 1000 in its own PID namespace with no network or AO state mounts. The
runner must prove exclusive volume references outside the namespace. The tool's
`/proc` checks do not prove absence of processes outside its PID namespace.

The tool opens the source `O_RDONLY|O_NOFOLLOW`, attaches its URI with
`mode=ro&immutable=1`, and verifies that every own FD referring to that inode has
read-only access. Source inode/size/mtime/ctime and absence of sidecars must still
match before commit. Immutable mode is allowed here only because the source is
sealed; it is unsafe for a live WAL database.

The candidate directory must not exist. The only destination database is the
fixed `candidate.sqlite3`, exclusively created 0600 in the new 0700 directory.
SQLite temporary files use that directory's `sqlite-tmp/`, on the same candidate
volume. A failure leaves private partial evidence for explicit owner cleanup;
it never writes a success receipt. No source or candidate file is removed.

```sh
ao-rowid-rebuild-copy \
  --snapshot /snapshot/run1/raw-audit-working.sqlite3 \
  --source-sha256 VERIFIED_CLOSED_SOURCE_SHA256 \
  --new-candidate-directory /candidate/run2 \
  --rebuild \
  --max-database-bytes 34359738368 \
  --wall-budget 6h
```

Omit `--rebuild` for schema preview; it creates only a new private inspection
directory and empty destination, and never copies application rows. `--wall-budget`
is configurable and has no hard-coded two-hour ceiling. The size budget applies
to each database, not total temporary spill; the runner must separately reserve
and limit the candidate volume's total space and memory. Run heavy work through
the explicitly selected authorized remote-compute host.

## Preservation and explicit refusals

- Every ordinary table preserves all hidden ROWIDs, including gaps, negative
  values, IDs above 2^53, and INTEGER PRIMARY KEY DESC's independent ROWID.
  `rowid`, `_rowid_`, or `oid` is selected only if it is not a declared column.
  If all three names are shadowed, the tool refuses.
- WITHOUT ROWID tables preserve their declared primary key and every value.
  Stored/virtual generated columns are regenerated by SQLite, then checked
  against the source with storage-class and binary-value equality.
- Tables use their original CREATE SQL. Indexes, views and triggers use their
  original SQL after all rows have been copied, so CDC triggers do not run while
  rebuilding. Every schema object's type/name/table/SQL must match the source.
- `sqlite_sequence` rows, hidden ROWIDs and high watermarks are copied exactly
  after autoincrement tables, including values above the largest surviving ID.
  Page size, text encoding, `user_version`, and `application_id` are preserved.
- Virtual/shadow tables, unknown hidden columns/schema kinds, unknown internal
  `sqlite_*` tables (including `sqlite_stat*`), unavailable custom collations or
  extensions, and a different reconstructed schema are refused. Statistics are
  never silently omitted or recomputed. A source containing statistics needs a
  separately reviewed preservation implementation before it is supported.

Before commit, each table has matching row counts, typed binary values and row
identity; ordinary tables also have independent ordered-ROWID SHA-256 digests on
both sides. The candidate must pass full `integrity_check(1)` and
`foreign_key_check`, and report `auto_vacuum=2`. The closed candidate is fsynced,
hashed, and checked for inode/permission stability. No body, prompt, token,
credential or source row ID is logged.

`rowid-rebuild-report.json` contains status `complete_unpublished`, source and
candidate SHA-256/bytes, schema-object count, actual read-only FD proof, and per
table row counts/ordered-ROWID digests. This proves a static copy's preservation;
it does not prove a production swap, replay, safe shutdown, sustained retention
capacity, or filesystem savings before actual candidate measurement.

## Targeted verification

Tests cover implicit ROWID rollback/ordering, rowid-name shadowing, generated and
WITHOUT ROWID tables, NULL/BLOB/NUL/invalid-UTF8 TEXT, storage types, sequence high
watermarks, CDC trigger silence, UTF-16, quoting, current application schema,
foreign-key failure and source/target path/reference/permission/digest guards.
The CLI build and `-h` smoke make no application or network requests.
